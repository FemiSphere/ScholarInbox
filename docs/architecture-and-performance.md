# 当前架构与性能边界

维护导航见 [代码地图](code-map.md)；操作与排障见 [维护指南](maintenance.md)。历史耗时和旧优化基准已移到 [2026-08-21 记录](history/2026-08-21-architecture-and-performance.md)，不用于推断当前吞吐。

## 执行顺序

```text
__main__ / 启动脚本 → cli.main
  → .env + 主 YAML（含 llm.preset 预设）+ 可选外置 LLM 配置
  → Gmail 读取 MIME / 邮件过滤
  → Scholar 本地解析；其他邮件有序分块 + AI 提取
  → 批内去重 + 近 30 天身份索引过滤
  → 研究兴趣画像（哈希缓存）
  → 初筛相关性（高/中/低/领域外/不相关）
  → 可选：高/中相关 → Search/Fetch 原始摘要 → 身份/原文核验 → 复评
  → 展示数量限制 → 只对展示的论文做中文标题与概述翻译 → MD / HTML
  → 核心成功且正式运行：更新索引；配置允许时标已读
```

联网补充仅在非 sample、`openai_compatible`、DeepSeek 官方主机且 `web_enrichment.enabled` 为真时生效。关闭它或使用其他后端时，沿用排序与翻译流程；`performance.separate_translation` 控制是否分离。sample 使用离线客户端。

## 数据边界

| 对象 | 含义与约束 |
| --- | --- |
| `EmailMessage` | 邮件原文及图片引用，提取输入 |
| `PaperEntry` | 邮件提取的标题、URL、DOI、片段；不覆盖为网络摘要 |
| `EvidenceRecord` | 身份匹配后取得的原始摘要、来源 URL 与核验元数据 |
| `RankedPaper` | 评级/得分/理由与中文翻译，独立附带证据 |
| `DigestRun` | 最终渲染输入，含统计与失败提示 |

思考分析决定评级，非思考翻译仅生成标题和中文概述；原始摘要优先于邮件片段，但不等于全文阅读。高相关不代表证据充分或科学结论已获核验。

## 失败与副作用

| 情况 | 输出 | 邮件/索引 |
| --- | --- | --- |
| 核心提取或初筛使用本地回退 | 尽可能输出并提示不完整 | 保持未读，不更新索引；已成功的评级/翻译留在结果缓存供重跑复用 |
| 仅翻译回退（评级完整） | 显示原英文标题/占位概述并提示 | 正常标已读、更新索引 |
| 可选来源不可用、核验失败或复评失败 | 保留初筛结果 | 核心成功时正常处理 |
| 用户取消/整次超时 | 保留已有缓存与请求日志 | 未到后续步骤则不执行；不承诺撤回已完成副作用 |
| `--dry-run` | 可生成输出、日志及本地缓存 | 不标已读、不保存索引 |

不要将可选失败送入 CLI 的核心回退计数，也不要让内部任务失败设置全局取消事件。已发出的外部请求无法撤回；阶段预算控制本地等待，不保证服务端停止计费。

## 并发与预算

阶段前后相继，默认提取/排序 worker 各 3，不是同时占 6。排序默认每批 10 篇；长邮件按条目/正文窗口拆块，截断只重分失败块。可选摘要复评串行批次共享剩余时间预算。

具体参数只在 [主模板](../config.example.yaml)、[LLM 预设](../literature_digest/presets/deepseek.yaml) 和对应专题维护；本地覆盖可能不同。整次预算、每封预算、逻辑请求预算与单次 socket 超时共同约束等待。

性能诊断先看阶段墙钟耗时，再看请求重叠、重试与 token。并发请求的耗时之和不能直接与运行墙钟时间比较。`scripts/benchmark_performance.py` 是模拟延迟的编排基准，不代表真实 API 速度或推荐准确率。

## 持久化

缓存、索引、TOC 图片在 `data/`；日报在 `outputs/`；日志与不含正文的指标在 `logs/`。具体保留/清理边界见 [维护指南](maintenance.md#目录与清理)。Search/Fetch 原始结果只存内存，唯一新增磁盘项是有界摘要 SQLite 缓存。
