## 已实施

- `logs/metrics/requests-*.jsonl` 实时追加请求开始、指标、状态、重试、JSON 修复、运行结束事件。文件不包含正文、提示词、认证头或响应原文。正常结束继续输出原有指标汇总；失败或中断保存已有指标。
- 解析每封邮件显示开始、完成、耗时、缓存命中与回退；排序显示批次与回退。失败不再静默。
- 邮件解析每次尝试最多 45 秒，排序最多 90 秒；每个逻辑 API 调用含重试和 JSON 修复总计最多 120 秒。默认最多重试一次，仅重试暂时网络错误及 HTTP 408、429、部分 5xx；鉴权、余额与证书错误不重试。
- 整次运行默认预算 600 秒，到期发出取消信号；配置 `performance.run_timeout_seconds: 0` 可关闭。网络轮询和队列在收到取消后退出，其他本地同步操作在下一个检查点响应取消。
- Ctrl+C 取消排队任务、停止后续 API 调用，退出码 130；运行预算到期退出码 124。已发出的 POST 无法撤回，服务端可能继续处理或计费；后台 HTTP 线程不会阻止进程退出，最多并存 8 个。
- 每封成功解析即时原子保存于 `data/cache/email_parsing/`。邮件内容、模型配置、解析选项变化时失效；API 失败后的规则回退不缓存。样例模式不读写生产解析缓存。缓存包含提取出的论文信息，仅存在本地被 Git 忽略的 data/ 中。
- `scripts/diagnose_deepseek.py` 可执行两次极小推理请求比较代理与直连，默认超时 20 秒，复用本地模型和 extra_body 设置。它会实际调用 API，输出仅含状态与耗时。
